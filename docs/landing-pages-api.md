# Landing page API contract

The frontend uses the existing digital API base URL (`VITE_DIGITAL_API_URL`)
and expects the API to store landing pages/slides in the existing landing-page
tables and `ProductContents` in a separate child table linked by `LandingPageId`
and the existing catalogue `ProductId`. A product's landing content is submitted
alongside the page; it is not written into the catalogue product record.
Product IDs may be numbers or strings (including GUIDs); preserve the catalog
ID exactly in slide/content payloads and checkout URLs.

## Create a landing page

`POST /api/LandingPage` (authenticated, JSON)

```json
{
  "Title": "Summer product launch",
  "Slug": "summer-product-launch",
  "Description": "Discover the details and shop the collection.",
  "BackgroundColor": "#f5f5f7",
  "TextColor": "#1d1d1f",
  "ButtonColor": "#0071e3",
  "IsPublished": true,
  "Slides": [
    {
      "SortOrder": 0,
      "Eyebrow": "New",
      "Title": "Product name",
      "Description": "Short promotional description",
      "ImageUrl": "https://cdn.example.com/products/hero.jpg",
      "ImageAlt": "Product shown from the front",
      "ImageHeight": 620,
      "ImageFit": "cover",
      "ProductId": "25e310b6-a3db-4661-9480-03d4f0dd91f2",
      "ButtonLabel": "Buy now"
    }
  ],
  "ProductContents": [
    {
      "ProductId": "25e310b6-a3db-4661-9480-03d4f0dd91f2",
      "Description": "Full product description.",
      "GalleryImages": [
        "https://cdn.example.com/products/front.jpg",
        "https://cdn.example.com/products/side.jpg"
      ],
      "VideoUrl": "https://cdn.example.com/products/demo.mp4",
      "Highlights": ["Feature one", "Feature two"],
      "Sections": [
        {
          "Title": "Design",
          "Content": "More product information."
        }
      ]
    }
  ]
}
```

`ProductContents` is optional; when present, persist each entry in the separate
landing-page product-content table and associate it with the new landing page
and catalogue product. The response should return the saved page, including
its generated `Id` and `ProductContents`, in the API's normal `data` envelope.
The `PUT /api/LandingPage/{id}` update endpoint should accept the same shape.
Create and update use the same page JSON contract. Each item in `Slides` is an
independent slideshow entry with its own uploaded `ImageUrl` and promotional
`Description`. Add more slideshow entries to upload more slide images.
`ProductContents[].GalleryImages` is a list of uploaded image URLs for that
product, so a single product can have any number of gallery images.
The admin list uses `GET /api/LandingPage`; public pages use
`GET /api/LandingPage/slug/{slug}` and should return only published pages,
including their slides and product contents. Deletion uses
`DELETE /api/LandingPage/{id}`.

## Upload landing-page media

`POST /api/LandingPage/media/uploadfile` (authenticated, multipart/form-data)

- Multipart field: `file`
- Accept image and video media. Enforce the **5 MB** maximum for videos on the
  server as well as in the browser.
- Store the file using the application's media-storage conventions and return
  its public URL in `data.url`, `data.imageUrl`, or `data.videoUrl`. The
  frontend resolves relative URLs against the digital API host so uploaded
  media renders in previews and published landing pages.

## cURL examples

Set `API` to the digital API origin and base path, then supply an admin bearer
token. Do not commit a real token to source control.

```sh
API="https://localhost:7254/api"
TOKEN="<admin-access-token>"

curl -X POST "$API/LandingPage" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @landing-page.json
```

Upload a slide/gallery image or a video first, then use the returned URL for
`Slides[].ImageUrl`, `ProductContents[].GalleryImages`, or
`ProductContents[].VideoUrl`. The landing-page editor collects files and
populates these URL fields in the JSON payload; admins do not need to enter
image paths manually:

```sh
curl -X POST "$API/LandingPage/media/uploadfile" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@product-demo.mp4;type=video/mp4"
```

Other endpoints:

```sh
curl -H "Authorization: Bearer $TOKEN" "$API/LandingPage"
curl -H "Authorization: Bearer $TOKEN" "$API/LandingPage/42"
curl -X PUT "$API/LandingPage/42" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary @landing-page.json
curl -X DELETE "$API/LandingPage/42" \
  -H "Authorization: Bearer $TOKEN"
curl "$API/LandingPage/slug/summer-product-launch"
```

The public URL generated by the frontend is
`https://<store-host>/p/<slug>`. Clicking **Buy now** navigates to
`/checkout?productId=<ProductId>` and uses the existing direct-checkout flow.
